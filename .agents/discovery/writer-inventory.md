# Page inventory for the writer: ocx Dev Container Feature docs

Companion to `use-cases.yaml` (tasks, needs, coverage, IA plan). Generated by the docs-plan
procedure on 2026-11-17. Location override: the skill default is `docs/discovery/`; this repo
uses `.agents/discovery/` so the plan stays off the published surface.

Not published. Do not copy the task wording ("As a ... I need to ... so that ...") into any page.

## 1. Conventions every page follows

- Site: Astro + Starlight with `@ocx-sh/theme`, `site/` in this repo, base `/integrations/devcontainer/`. Pages live under `site/src/content/docs/`. Frontmatter holds `title` and `description` only.
- Format: `.md` for every page. No page needs a component. Use `.mdx` only if a page later needs `Tabs`, and then declare with `{/* doc_type: how-to */}`.
- Declaration: two comment lines inside the first 12 lines, below the frontmatter closing `---`, never as YAML. `doc_tier` only on `how-to` and `landing`. Exact lines are in each page entry.
- Anchors: every heading another page links to carries `{#kebab-id}`. The H2 lists below give the ids.
- Every page ends with `## Next steps {#next-steps}` (how-to) or a related-links block, except `reference` and `changelog`.
- Examples: each runnable example below has a slug. The test is `test/ocx/<slug>.sh` (a scenario in `test/ocx/scenarios.json` named `<slug>` when the example is a `devcontainer.json`), and its header carries `# doc: <slug>`. A harness step (docs-instrument) extracts the page fence, swaps the feature reference `ghcr.io/ocx-sh/devcontainer-features/ocx:<tag>` for the local id `ocx`, and diffs the options against the scenario. A fence that cannot run is wrapped in a no-run marker with a reason (DOC-EX-06). Fence info strings are one hyphen-joined token (`jsonc-norun`).
- Failure messages in troubleshooting and in "what you see" fences are pasted from a real failing run of the built feature, and a `fail-*` scenario asserts the text. Never write a message from memory.
- URLs: use `setup.ocx.sh` and GitHub URLs only. `https://ocx.sh/` served an expired certificate on 2026-11-16; check it again before linking `ocx.sh` doc pages.
- Product shape `cli`: first-steps budget is at most 9 actions and about 100 words before the first command.

## 2. Facts the writer must take from the built feature, not from this plan

`.agents/research/runtime-contract.md` did not exist when this plan was written. These
facts decide page content and are assumptions until the implementation or that file settles
them. Each page entry marks the dependency with `[R]`.

| Fact | Assumption used here |
|---|---|
| Lifecycle command that runs the restore | one that a Codespaces prebuild also runs (`updateContentCommand` or `onCreateCommand`), as `remoteUser`. If it is `postCreateCommand`, the prebuild page must say the store is not warmed by a prebuild |
| Restore with `ocx.toml` and no `ocx.lock` | the container still starts, a warning names `ocx lock`; observed command exit is 78 (friction log T04) |
| Restore with no `ocx.toml` | silent no-op, exit 0 (observed command exit is 64, the hook guards it) |
| Consent default | `consentPaths` default `/workspaces/*`, so a fresh checkout activates at the first prompt |
| Version marker file | `/usr/local/share/ocx-feature/ocx-version` holds the pinned ocx version |
| `caBundle` | a path inside the image only. Inline PEM is not accepted |
| `ocxHome` | unset means each user keeps `~/.ocx`. Set means `OCX_HOME` in `containerEnv`, and the page states who can use it |
| Install exit codes | the installer's table: 0 ok, 1 generic, 2 usage or missing tool, 3 network, 4 checksum, 5 extract, 7 platform. Exit 6 is not used, because `ocx self setup` never runs |

### P18 `reference/installer-parity.md`

- Title: Installer variables and feature options
- Type: `reference`. Declaration: `<!-- doc_type: reference -->`
- Need: T13. Outcome: every `OCX_INSTALL_*` variable has a destination or a stated reason.
- H2: `## Installer variables {#variables}`, `## Installer flags {#flags}`, `## Shared ocx variables {#shared}`, `## Deliberately absent {#absent}`, `## Options with no installer counterpart {#feature-only}`.
- Closed tier legend above the table, as `page_type.py` expects: `exposed`, `fixed`, `not-exposed` (DOC-DISC-24). Rows below are the starting decisions; the implementer may move a row, the reason column stays.

| Installer name | Feature option | Tier | Reason |
|---|---|---|---|
| `OCX_INSTALL_VERSION` | `version` | exposed | default is `pinned`, not the installer's newest stable |
| `OCX_INSTALL_DIST_URL` | `distUrl` | exposed | replaces the baked snapshot |
| `OCX_INSTALL_MIRROR_URL` | `mirrorUrl` | exposed | archive URL becomes `<mirror>/<tag>/<filename>` |
| `OCX_INSTALL_CA_BUNDLE` | `caBundle` | exposed | path inside the image only |
| `OCX_INSTALL_NO_SETUP` | none | fixed | always on: the build never runs `ocx self setup` |
| `OCX_INSTALL_DOWNLOADER` | none | not-exposed | probed automatically, curl then wget |
| `OCX_INSTALL_FORCE` | none | not-exposed | a rebuild installs fresh; a repeat run replaces the binary |
| `OCX_INSTALL_NO_SMOKETEST` | none | not-exposed | the smoke test always runs |
| `OCX_INSTALL_PRINT_PATH` | none | not-exposed | the build log is not parsed; the path is `installDir` |
| `OCX_INSTALL_QUIET` | none | not-exposed | build output stays visible for failures |
| `OCX_INSTALL_REPO` | none | not-exposed | the installer uses it only in an error message |
| `OCX_HOME` | `ocxHome` | exposed | per-user store by default |
| `OCX_NO_MODIFY_PATH` | none | fixed | the feature edits no profile |
| `OCX_MANAGED_CONFIG` | `managedConfig` | exposed | also synced at first start [R] |

- Deliberately absent: no checksum off-switch, no credential option; `OCX_AUTH_*`, `OCX_NO_VERIFY` and `OCX_ALLOW_YANKED` stay in the user's `containerEnv` or in managed configuration.
