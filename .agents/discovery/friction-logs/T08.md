# Friction log: T08 install ocx where the builder has no route to the internet (status quo, no feature yet)

## Context

A platform engineer who has never mirrored ocx, building a container on a runner that blocks
all public hosts. They run the official one-liner and expect either a clear failure or a hint
about mirrors. Run on 2026-11-17 against `alpine:3` with `--network none`. Written by the
planning agent with the repository in context, not by a subagent without it. The mirror
variables were read from the installer docs, not run; those parts are predicted, not observed.

## Pros and cons

- Bad: the failure message names a DNS error but not that the whole install needs a reachable manifest host and a reachable GitHub, nor that a mirror setting exists.
- Bad: the shell printed exit 0 for the pipeline although nothing was installed.
- Predicted, not observed: with `OCX_INSTALL_MIRROR_URL` set, a mirror that later requires login fails with an error that looks like a network fault, the same shape find_ocx documents for a locked mirror.

## Detailed stream of consciousness

```text
$ docker run --rm --network none alpine:3 sh -c 'wget -qO- https://setup.ocx.sh/sh | sh; echo exit=$?'
wget: bad address 'setup.ocx.sh'
exit=0
```

The install script itself could not even be fetched, so no mirror knob can help before the
script is available. A reader in this position needs the script, the release manifest and the
archive all from inside the network. Nothing in this output says that. I would stop here and
search for "offline install ocx".
