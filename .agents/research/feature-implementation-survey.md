## 1. Shebang and shell dialect

**What the spec and CLI do.**
- Spec: `install.sh` runs as root; the execute bit is set and the file is invoked directly, so the shebang decides the interpreter. The spec "recommends" a shell available by default in the target distros ("`bash` in Debian/Ubuntu or Fedora, `sh` in Alpine") and explicitly blesses a bootstrap pattern: check for the desired shell, install it if missing, then invoke a secondary script ([spec: Invoking install.sh](https://github.com/devcontainers/spec/blob/main/docs/specs/devcontainer-features.md)).
- The CLI's generated wrapper `devcontainer-features-install.sh` is `#!/bin/sh` with `set -e`, sources `devcontainer-features.builtin.env` and `devcontainer-features.env` under `set -a`, then does `chmod +x ./install.sh && ./install.sh` ([cli: containerFeaturesConfiguration.ts](https://github.com/devcontainers/cli/blob/main/src/spec-configuration/containerFeaturesConfiguration.ts)). The framework itself therefore needs only `/bin/sh`, `chmod`, `cut` and `getent`-equivalent on the image.
- **[ran]** `#!/usr/bin/env bash` on plain `alpine:3.20` fails with `env: can't execute 'bash': No such file or directory`, exit 127. A script with no shebang and `local` runs fine under busybox `sh` when invoked from the wrapper (kernel ENOEXEC fallback to the calling shell); aqua relies on this (below).

Pattern: the reference collection is bash-first and mostly Debian/RHEL; vendor single-binary features lean POSIX sh (6 of the 9 vendor/community single-tool scripts read are `#!/bin/sh` or shebang-less). Bash is used where the script needs arrays/`[[ ]]`/`declare -g` (copy-pasted `find_version_from_git_tags` helpers) or where the vendor was written Debian-first.

**Dialect caveat even in "sh" scripts.** Doppler, claude-code, k6 and aqua use `local` (not POSIX, but supported by dash, busybox ash and bash), `echo -n`, and k6 uses `grep -oP` in its Go-version path (busybox grep has no `-P`: not run, standard busybox behaviour). `common-utils/install.sh` uses `echo -e` under `#!/bin/sh`; **[ran]** on `debian:12-slim` (`/bin/sh` -> dash) this prints a literal `-e `, so its non-root error message is garbled on Debian. Minor, but shows "sh" scripts are not tested on dash for every path.

Consequences:
- Bash-required fails outright on plain Alpine, Wolfi/Chainguard, busybox. `devcontainers/base:alpine` works only because it is `alpine` plus the `common-utils` feature ([Dockerfile](https://github.com/devcontainers/images/blob/main/src/base-alpine/.devcontainer/Dockerfile), [devcontainer.json](https://github.com/devcontainers/images/blob/main/src/base-alpine/.devcontainer/devcontainer.json)), which is what installs bash. A user who applies a feature to bare `alpine` gets no bash unless `common-utils` runs first (and `installsAfter` is only a soft ordering hint: it does not pull `common-utils` in, see [spec: installsAfter](https://github.com/devcontainers/spec/blob/main/docs/specs/devcontainer-features.md)).
- Debian/Ubuntu images ship neither curl, wget nor CA certificates, so every downloader-based feature must install them (`check_packages curl ca-certificates`); devcontainers `git`/`node` do ([git/install.sh](https://github.com/devcontainers/features/blob/main/src/git/install.sh)). Earthly uses bare `wget` with no probing or install, so it only works on images that already have wget (**[ran]**: `debian:12-slim` has none); its tests use only `devcontainers/base:ubuntu` ([earthly scenarios](https://github.com/earthly/devcontainer-features/blob/main/test/earthly/scenarios.json)).
- RHEL-minimal family (`ubi-minimal`, `rockylinux:9-minimal`, `amazonlinux`) has curl but no `tar`/`gzip`: an installer that extracts `.tar.gz` must install `tar` (+`gzip`) there. Devcontainers features run `microdnf`/`dnf` for such cases ([node/install.sh](https://github.com/devcontainers/features/blob/main/src/node/install.sh)).
- Scratch/distroless: no feature handles it; the wrapper itself needs `/bin/sh` so features cannot work there. Not a supported target of any surveyed feature.

**De-facto supported base-image set** (from reference READMEs and scenario matrices):
- `common-utils` README: "recent versions of Debian/Ubuntu, RedHat Enterprise Linux, Fedora, RockyLinux, and Alpine Linux" ([NOTES.md](https://github.com/devcontainers/features/blob/main/src/common-utils/NOTES.md)). Its scenarios cover `debian:bookworm/trixie`, `ubuntu:jammy/noble/resolute`, `alpine` + `alpine:3.14/3.15/3.18`, `fedora`, `rockylinux:8/9` (+`-minimal`), `almalinux:8/9` (+`-minimal`), `ubi8`, `centos:7`, `mcr.microsoft.com/cbl-mariner/base/core:2.0`, `mcr.microsoft.com/dotnet/sdk:8.0-azurelinux3.0`, `mcr.microsoft.com/devcontainers/base:{ubuntu,jammy,alpine}` ([scenarios.json](https://github.com/devcontainers/features/blob/main/test/common-utils/scenarios.json)).
- `git`: Alpine, Debian/Ubuntu, RHEL, Fedora, Alma, Rocky with `apk`/`apt`/`yum`/`dnf`/`microdnf` ([NOTES.md](https://github.com/devcontainers/features/blob/main/src/git/NOTES.md)); tests also include Mariner and CentOS 7 ([scenarios](https://github.com/devcontainers/features/blob/main/test/git/scenarios.json)).
- `node`: Debian/Ubuntu/RHEL/Fedora/Alma/Rocky, **no Alpine** (`echo "Linux distro ${ID} not supported."; exit 1`) ([NOTES.md](https://github.com/devcontainers/features/blob/main/src/node/NOTES.md), [install.sh](https://github.com/devcontainers/features/blob/main/src/node/install.sh)).
- `github-cli`, `docker-in-docker`: "Debian/Ubuntu-based distributions with the `apt` package manager" ([github-cli NOTES](https://github.com/devcontainers/features/blob/main/src/github-cli/NOTES.md), [dind NOTES](https://github.com/devcontainers/features/blob/main/src/docker-in-docker/NOTES.md)); Alpine support is an open PR [#1739](https://github.com/devcontainers/features/pull/1739) and open issues [#751](https://github.com/devcontainers/features/issues/751), [#890](https://github.com/devcontainers/features/issues/890), [#498](https://github.com/devcontainers/features/issues/498).
- devcontainers-extra narrowed to Debian/Ubuntu: "Limiting support only to Debian/Ubuntu based Dev Containers" ([issue #244](https://github.com/devcontainers-extra/features/issues/244), [README](https://github.com/devcontainers-extra/features/blob/main/README.md)).
- Distros outside that set are served by forks: Wolfi ([davzucky](https://github.com/davzucky/devcontainers-features-wolfi/blob/main/README.md): "Most of the features available for devcontainers usually expect you to run a debian (or derived) base image"), Alpine ([cirolosapio](https://github.com/cirolosapio/devcontainers-features/blob/main/README.md), `alpine-*` features), Arch ([bartventer](https://github.com/bartventer/arch-devcontainer-features/blob/main/README.md)), Amazon Linux 2 ([customink](https://github.com/customink/codespaces-features/blob/main/README.md)). No `zypper` (openSUSE) code exists in any script read.

**Declaring vs detecting OS.** There is no declarative mechanism: [spec issue #58](https://github.com/devcontainers/spec/issues/58) ("Supported Architectures/OS", proposing `architectures` and `osVersion`) is still open. Features detect at runtime:
- `/etc/os-release` `ID`/`ID_LIKE` -> an `ADJUSTED_ID` of `debian|rhel|alpine`, rejecting anything else with "not supported" ([git/install.sh](https://github.com/devcontainers/features/blob/main/src/git/install.sh)).
- Package-manager probing in order `apt-get`, `apk`, `microdnf`, `dnf`, `yum` (`type x >/dev/null 2>&1`) ([git](https://github.com/devcontainers/features/blob/main/src/git/install.sh), [Doppler](https://github.com/DopplerHQ/devcontainer-features/blob/main/src/doppler-cli/install.sh), [claude-code](https://github.com/anthropics/devcontainer-features/blob/main/src/claude-code/install.sh)); dind also probes `tdnf` ([dind](https://github.com/devcontainers/features/blob/main/src/docker-in-docker/install.sh)).
- libc detection for prebuilt binaries: `/sbin/apk` or `ldd --version | grep musl` or `/lib/ld-musl-*` ([bun/install.sh](https://github.com/devcontainers-extra/features/blob/main/src/bun/install.sh), [library_scripts.sh](https://github.com/devcontainers-extra/features/blob/main/src/bun/library_scripts.sh)).

## 2. Install skeleton patterns

**Root check.** `if [ "$(id -u)" -ne 0 ]; then echo 'Script must be run as root...'; exit 1; fi` ([common-utils](https://github.com/devcontainers/features/blob/main/src/common-utils/install.sh), [node](https://github.com/devcontainers/features/blob/main/src/node/install.sh), [duckdb-cli](https://github.com/eitsupi/devcontainer-features/blob/main/src/duckdb-cli/install.sh)). Redundant since the wrapper runs as root, but cheap and shared.

**`set` flags.** `set -e` is near-universal; `set -eu` in claude-code, aqua; `set -xeuo pipefail` in Tailscale (bash only: `pipefail` is not in dash).

**Options.** The CLI exports options as upper-cased env vars with non-word chars -> `_` (`installYarnUsingApt` -> `INSTALLYARNUSINGAPT`, hyphens -> underscores) and defaults omitted options to their `default` ([spec: Option Resolution](https://github.com/devcontainers/spec/blob/main/docs/specs/devcontainer-features.md)). Scripts re-default defensively: `VERSION="${VERSION:-latest}"` ([Doppler](https://github.com/DopplerHQ/devcontainer-features/blob/main/src/doppler-cli/install.sh)), `INSTALL_ZSH="${INSTALLZSH:-"true"}"` ([common-utils](https://github.com/devcontainers/features/blob/main/src/common-utils/install.sh)). Camel-case option names flatten to unreadable env names, so authors keep a single alias line per option.

**Package-manager abstraction.**
- `check_packages` + `pkg_mgr_update` with an `apt-get update` guard (`[ "$(find /var/lib/apt/lists/* | wc -l)" = "0" ]`) and, for rpm, `microdnf makecache` / `dnf check-update` guarded by cache-dir emptiness ([node](https://github.com/devcontainers/features/blob/main/src/node/install.sh), [dind](https://github.com/devcontainers/features/blob/main/src/docker-in-docker/install.sh)). trunk copies the apt-only variant and so is Debian-only despite `#!/bin/sh` ([trunk](https://github.com/trunk-io/devcontainer-feature/blob/main/src/trunk/install.sh)).
- Cleanup: `rm -rf /var/lib/apt/lists/*` at start and end; `rm -rf /var/cache/apk/*`; `rm -rf /var/cache/dnf/* /var/cache/yum/*`; `apk add --no-cache` avoids needing cleanup ([git](https://github.com/devcontainers/features/blob/main/src/git/install.sh)).
- devcontainers-extra's `clean_download`: if neither curl nor wget exists, install wget temporarily, download, then purge it and restore the saved apt lists / apk state ([library_scripts.sh](https://github.com/devcontainers-extra/features/blob/main/src/bun/library_scripts.sh)). Supports only apt-get and apk ("distro not supported" otherwise). The comment states the reason for avoiding `trap ... RETURN`: "alpine lack bash".

**Architecture mapping.** `uname -m` with `x86_64|amd64` -> `amd64`, `aarch64|arm64` -> `arm64` ([Doppler](https://github.com/DopplerHQ/devcontainer-features/blob/main/src/doppler-cli/install.sh), [Earthly](https://github.com/earthly/devcontainer-features/blob/main/src/earthly/install.sh), [Tailscale](https://github.com/tailscale/codespace/blob/main/src/tailscale/install.sh), [bun](https://github.com/devcontainers-extra/features/blob/main/src/bun/install.sh)). Debian-only features use `dpkg --print-architecture` and thereby cannot run on Alpine/rpm ([duckdb-cli](https://github.com/eitsupi/devcontainer-features/blob/main/src/duckdb-cli/install.sh), [github-cli](https://github.com/devcontainers/features/blob/main/src/github-cli/install.sh)); dind falls back `dpkg ... || uname -m` and `rpm --eval '%{_arch}'` for rpm ([dind](https://github.com/devcontainers/features/blob/main/src/docker-in-docker/install.sh)). Armv7/i386 are mapped by Doppler and k6 only. Unsupported arch -> explicit `exit 1` with message (Tailscale, duckdb-cli).

**Version resolution (`latest`).**
- Reference features use a copy-pasted `find_version_from_git_tags` that runs `git ls-remote --tags` and `grep -oP` (needs GNU grep) ([github-cli](https://github.com/devcontainers/features/blob/main/src/github-cli/install.sh)). Issue [#1726](https://github.com/devcontainers/features/issues/1726) shows this exits 1 when GitHub rations unauthenticated git ("could not read Username"), affecting 15 of 28 features, with measurements that the `git-upload-pack` POST is rationed but plain HTTPS is not; fixed by [PR #1744](https://github.com/devcontainers/features/pull/1744), which added a REST (`api.github.com/repos/.../tags`) fallback in [github-cli/scripts/version-resolution.sh](https://github.com/devcontainers/features/blob/main/src/github-cli/scripts/version-resolution.sh). Earlier rate-limit report: [#911](https://github.com/devcontainers/features/issues/911) (docker compose releases API, intermittent).
- Alternatives that avoid the API: follow the `https://github.com/<o>/<r>/releases/latest` redirect and read `Location` (k6: `wget --spider -S ... | grep Location`, [k6 common](https://github.com/grafana/devcontainer-features/blob/main/src/k6/install-k6-xk6-common.sh)); use the `releases/latest/download/<asset>` URL directly (Earthly); vendor "stable/latest" URLs (Tailscale, micromamba `micro.mamba.pm/api/.../latest`); upstream installer script (Doppler, trunk, mise).
- Fallback-one-version-back when the newest tag has no asset yet (github-cli `find_prev_version_from_git_tags`, same file).
- Retries: GPG key fetch loops 5x with 10 s sleep ([github-cli](https://github.com/devcontainers/features/blob/main/src/github-cli/install.sh)); Doppler uses `curl --retry 3`; aqua `curl --retry 5`. No surveyed single-binary feature retries download of the main artifact except those two.

**Checksum / signature verification** (counts of `sha256|checksum|gpg` per script, devcontainers/features): terraform 115, python 56, kubectl-helm-minikube 19 (`sha256sum -c`, `*_SHA256` options with an `automatic`/`dev-mode` escape), dind 9, powershell 5, git-lfs 5 (GPG-decrypts `sha256sums.asc`); node, git, github-cli (GPG only for apt repo key), common-utils, hugo, aws-cli: none for binaries ([kubectl-helm-minikube](https://github.com/devcontainers/features/blob/main/src/kubectl-helm-minikube/install.sh), [git-lfs](https://github.com/devcontainers/features/blob/main/src/git-lfs/install.sh), [terraform](https://github.com/devcontainers/features/blob/main/src/terraform/install.sh)). Vendors: Doppler verifies a detached GPG signature for pinned versions (`gpgv`, installs `gpgv` first) but uses the vendor's `curl | bash` for `latest`; aqua pins the upstream installer by commit SHA (`# v4.1.1`) and the installer verifies; Wolfi `mise` delegates to `mise.run` (comment: "verifies its checksum"); Earthly, trunk, Tailscale, micromamba, duckdb-cli, k6: **no verification**; nanolayer in devcontainers-extra is fetched from a GitHub release pinned to `v0.5.6` with no checksum ([library_scripts.sh](https://github.com/devcontainers-extra/features/blob/main/src/bun/library_scripts.sh)).

**Install location.** `/usr/local/bin` for single binaries (Doppler, Earthly `LOCATION` option default `/usr/local/bin`, k6, Tailscale, micromamba, Wolfi mise); `/usr/bin` (duckdb-cli). Per-user home only for tools whose installer is per-user (aqua: `~/.local/share/aquaproj-aqua/bin`, added to `remoteEnv.PATH` in its scenarios, [aqua scenarios](https://github.com/aquaproj/devcontainer-features/blob/main/test/aqua-installer/scenarios.json)). Shared-prefix tools use group ownership: micromamba `/opt/conda` with a `conda` group, `chown -R`, `chmod g+rw`, `usermod -aG` ([micromamba](https://github.com/mamba-org/devcontainer-features/blob/main/src/micromamba/install.sh)).

**`_REMOTE_USER` handling.**
- Spec: `_REMOTE_USER`, `_CONTAINER_USER`, `_REMOTE_USER_HOME`, `_CONTAINER_USER_HOME` are provided; if `remoteUser` is unset `_REMOTE_USER` equals `_CONTAINER_USER` ([spec: User environment variables](https://github.com/devcontainers/spec/blob/main/docs/specs/devcontainer-features.md)). The CLI computes the HOMEs via passwd lookup into the builtin env file ([cli](https://github.com/devcontainers/cli/blob/main/src/spec-configuration/containerFeaturesConfiguration.ts)).
- Convention: `USERNAME="${USERNAME:-"${_REMOTE_USER:-"automatic"}"}"`, then `automatic` probes `vscode`, `node`, `codespace`, then uid 1000, else root; `none` or unknown -> root ([node](https://github.com/devcontainers/features/blob/main/src/node/install.sh), [duckdb-cli](https://github.com/eitsupi/devcontainer-features/blob/main/src/duckdb-cli/install.sh)). Prefer `_REMOTE_USER_HOME` over `eval ~user` when writing per-user files.
- Run as user: `su ${USERNAME} -c "..."` (spec-recommended) or `sudo -u "$_REMOTE_USER"` (aqua; installs `sudo` if missing; uses `$_REMOTE_USER` unguarded under `set -u`).

**PATH/env exposure.** Three mechanisms:
1. `containerEnv` in `devcontainer-feature.json` (`PATH` with `${PATH}` prepend; go sets `GOROOT`, `GOPATH`, `PATH`) ([go feature json](https://github.com/devcontainers/features/blob/main/src/go/devcontainer-feature.json)). Applies to all processes; no shell involvement. Used by go, node, python, rust, hugo, nix, dind.
2. `/etc/profile.d/*.sh` (Wolfi mise: `PATH` and shims, [mise](https://github.com/davzucky/devcontainers-features-wolfi/blob/main/src/mise/install.sh)); go/hugo/node additionally write `/etc/profile.d/00-restore-env.sh` to undo login-shell PATH resets (`export PATH=${PATH//$(sh -lc 'echo $PATH')/\$PATH}`) ([go](https://github.com/devcontainers/features/blob/main/src/go/install.sh)).
3. rc-file edits: node `updaterc()` appends once to `/etc/bash.bashrc`+`/etc/zsh/zshrc` (Debian) or `/etc/bashrc`+`/etc/zshrc` (RHEL) guarded by `[[ "$(cat $rc)" != *"$1"* ]]`, controlled by an `UPDATE_RC` option ([node](https://github.com/devcontainers/features/blob/main/src/node/install.sh)); micromamba edits `~/.bashrc`/`~/.zshrc` with a grep marker ([micromamba](https://github.com/mamba-org/devcontainer-features/blob/main/src/micromamba/install.sh)). Alpine has no `/etc/bash.bashrc`, so these helpers skip Alpine (node doesn't support it).
A binary in `/usr/local/bin` needs none of these.

**Shell completion.** Few features install completions: Earthly runs `earthly bootstrap --with-autocomplete` ([Earthly](https://github.com/earthly/devcontainer-features/blob/main/src/earthly/install.sh)); micromamba `shell init`; Arch terraform has an `ENABLESHELLCOMPLETION` option ([arch terraform](https://github.com/bartventer/arch-devcontainer-features/blob/main/src/terraform/install.sh)). None of the vendor single-binary features drop completion files into `/usr/share/bash-completion/completions` / zsh `site-functions`: gap, not a convention.

**Idempotence (feature applied twice / image reused).** Mechanisms seen: marker files (`MARKER_FILE=/usr/local/etc/vscode-dev-containers/common` in common-utils), `type tool` skip guarded by an `ALLOWREINSTALL` option (micromamba), grep-before-append in rc files (node, micromamba), `mkdir -p`, `MISE_INSTALL_SKIP_IF_EXISTS=1` (Wolfi mise). The CLI's `--skip-duplicated`/duplicate tests install the same feature twice with randomized options ([cli test.md](https://github.com/devcontainers/cli/blob/main/docs/features/test.md)). Earthly/trunk/Doppler overwrite the binary unconditionally (idempotent by overwrite).

## 3. Option design conventions

- Universal: `version`, default `latest`, type string, with `proposals` (free-form allowed), e.g. Doppler (no proposals, description gives example), k6 `proposals: ["latest","1.0.0"]`, github-cli `proposals: ["latest","none"]`, git `proposals: ["latest","system","os-provided"]` default `os-provided` ([Doppler json](https://github.com/DopplerHQ/devcontainer-features/blob/main/src/doppler-cli/devcontainer-feature.json), [k6 json](https://github.com/grafana/devcontainer-features/blob/main/src/k6/devcontainer-feature.json), [git json](https://github.com/devcontainers/features/blob/main/src/git/devcontainer-feature.json)). `none` is a common sentinel to skip a sub-tool.
- `enum` (strict) is rare: 16 devcontainers features carry 1-4 `enum`/`proposals` each, mostly `proposals`. Spec: `proposals` = suggestions, free-form allowed; `enum` = strict, free-form rejected ([spec: options](https://github.com/devcontainers/spec/blob/main/docs/specs/devcontainer-features.md)). Version fields use `proposals` because users need arbitrary pins.
- Advanced knobs seen: `LOCATION` (Earthly, install dir), `BOOTSTRAP` (boolean), `installDirectlyFromGitHubRelease`, `extensions` comma-separated list (github-cli), `with`/`xk6-version`/`go-version` (k6), `updateRc`, `username`, `*_SHA256` (kubectl-helm-minikube). Bloat appears where one feature wraps several tools (kubectl-helm-minikube, terraform with 6 sub-tools and 6 SHA options); single-tool vendor features keep 1-3 options.
- Option names are flattened to env vars (see section 2), so prefer lowercase single-word or camelCase names with an obvious upper-case form; hyphenated names (`xk6-version`, `go-version`) work but map to `XK6_VERSION`.
- Spec fields worth using: `documentationURL`, `licenseURL`, `keywords`, `installsAfter`, `legacyIds`, `deprecated`, `customizations`, `mounts`, `capAdd`, `entrypoint`, `containerEnv` ([spec: devcontainer-feature.json properties](https://github.com/devcontainers/spec/blob/main/docs/specs/devcontainer-features.md)). Copilot hint text under `customizations.vscode.settings["github.copilot.chat.codeGeneration.instructions"]` appears in the newer devcontainers features ([git json](https://github.com/devcontainers/features/blob/main/src/git/devcontainer-feature.json)).

## 4. Testing practice

**Mechanics** ([cli docs/features/test.md](https://github.com/devcontainers/cli/blob/main/docs/features/test.md), [testCommandImpl.ts](https://github.com/devcontainers/cli/blob/main/src/spec-node/featuresCLI/testCommandImpl.ts)):
- Layout: `src/<id>/`, `test/<id>/test.sh` (auto-generated test: a devcontainer with the feature, default options, `--base-image`, `--remote-user`, default `root`), `test/<id>/scenarios.json` + `<scenario>.sh`, `test/<id>/duplicate.sh`, `test/_global/` (cross-feature scenarios).
- Flags: `-f/--features`, `-i/--base-image`, `--remote-user`, `--skip-scenarios`, `--skip-autogenerated`, `--skip-duplicated`, `--global-scenarios-only`, `--filter`.
- Scenario `<name>.sh` must match the scenario key; a scenario can set `build.dockerfile` for a custom image (aqua uses it for `alpine-nonroot`), `remoteUser`, `remoteEnv`, `containerEnv`.
- Test scripts use `source dev-container-features-test-lib` giving `check <label> <cmd...>` and `reportResults`. That lib is **bash** (`#!/bin/bash`, arrays, `echo -e`) generated by the CLI ([utils.ts](https://github.com/devcontainers/cli/blob/main/src/spec-node/featuresCLI/utils.ts)). Consequence: on bash-less images (Alpine/Wolfi) the test scripts cannot source it unless bash is installed first. Doppler solved this with a POSIX snippet `_ensure_bash.sh` that installs bash via apk/apt/dnf/yum before sourcing the lib ([_ensure_bash.sh](https://github.com/DopplerHQ/devcontainer-features/blob/main/test/volume-permissions/_ensure_bash.sh)); other features test Alpine only on `devcontainers/base:alpine` (git, k6).

**Typical matrices.**
- Reference CI ([test-pr.yaml](https://github.com/devcontainers/features/blob/main/.github/workflows/test-pr.yaml)): `dorny/paths-filter` detects changed features; job 1 `devcontainer features test --skip-scenarios -f <feature> -i <baseImage>` over `ubuntu:jammy, debian:12, mcr.../base:ubuntu, mcr.../base:debian, mcr.../base:noble` with per-feature excludes; job 2 `--skip-autogenerated` scenarios on a larger runner; separate isolated jobs for flaky scenarios (dind iptables); `continue-on-error: true`. Release via `devcontainers/action` with `publish-features` + `generate-docs` ([feature-starter release.yaml](https://github.com/devcontainers/feature-starter/blob/main/.github/workflows/release.yaml)); `validate-only` job for the JSON ([validate.yml](https://github.com/devcontainers/feature-starter/blob/main/.github/workflows/validate.yml)).
- feature-starter has three jobs: `test-autogenerated` (features x `debian:latest, ubuntu:latest, mcr.../base:ubuntu`), `test-scenarios` (`--skip-autogenerated --skip-duplicated`), `test-global` (`--global-scenarios-only`) ([test.yaml](https://github.com/devcontainers/feature-starter/blob/main/.github/workflows/test.yaml)). Grafana copies it verbatim ([test.yaml](https://github.com/grafana/devcontainer-features/blob/main/.github/workflows/test.yaml)) and adds global scenarios for `mcr base:{ubuntu,debian,alpine}` ([_global scenarios](https://github.com/grafana/devcontainer-features/blob/main/test/_global/scenarios.json)).
- Scenario base-image matrices in practice: `common-utils` ~25 images (list in section 1), `git` ~12, `node` ~18, `docker-in-docker` ~11 (all in `test/<id>/scenarios.json` in devcontainers/features). Doppler: `ubuntu:latest, debian:latest, alpine:latest, fedora:latest, mcr base:ubuntu`, plus a pinned-version scenario ([scenarios](https://github.com/DopplerHQ/devcontainer-features/blob/main/test/doppler-cli/scenarios.json)). aqua: `debian:bookworm-<date>` (pinned digest-like tag) x2 versions, `alpine:3.19.1`, custom Dockerfile for non-root Alpine ([scenarios](https://github.com/aquaproj/devcontainer-features/blob/main/test/aqua-installer/scenarios.json)). Tailscale: `ubuntu:latest`, `almalinux:latest` ([scenarios](https://github.com/tailscale/codespace/blob/main/test/tailscale/scenarios.json)). eitsupi: base-image list `debian:stable-slim, ubuntu:jammy, ubuntu:noble, mcr base:{ubuntu,debian}` x `amd64`/`arm64` on `ubuntu-24.04` / `ubuntu-24.04-arm` runners ([test.yaml](https://github.com/eitsupi/devcontainer-features/blob/main/.github/workflows/test.yaml)).
- Typical assertions are shallow: `check "version" git --version`, `check "doppler is installed" command -v doppler`, version-format regex. The better ones compare against upstream: k6 `test.sh` fetches the latest release redirect and asserts `k6 --version` matches ([k6 test.sh](https://github.com/grafana/devcontainer-features/blob/main/test/k6/test.sh)). Non-root and root are rarely both tested (aqua is the exception).

**bats.** No bats usage found in any surveyed repo: no `*.bats` file and no bats/shunit2/shellspec reference in the git trees of devcontainers/features, devcontainers-extra, grafana, Doppler, aqua, mamba-org, rocker-org, eitsupi, jsburckhardt, tailscale, coder, bartventer, davzucky, devcontainers-community, meaningful-ooo (tree scan by filename, 2026-11-16). One index entry, [brokenpip3/devcontainers-bats](https://github.com/brokenpip3/devcontainers-bats), is a feature that *installs* bats; not read further. GitHub code search for bats + devcontainer features returned nothing. So the devcontainer CLI is the only observed testing tool; shell-level unit testing is not an established practice here.

**Cleanest split if we want more than the CLI** (design inference, not observed practice):
1. **Unit/dialect layer (bats-core or plain `sh`)**: source `install.sh` functions (arch mapping, version/URL building, checksum parse, os-release classification) with stubbed `uname`, `curl`/`wget`, `apk`/`apt-get` on `PATH`; run the same file under `dash`, `busybox sh` and `bash --posix` (this is what catches `local`, `echo -e`, `[[ ]]` mistakes). Fast, no Docker. Requires `install.sh` to be sourceable (`main` guard) and without network at source time.
2. **Per-image smoke layer (plain `docker run`, bats optional as the runner)**: mount the feature dir into `alpine`, `wolfi-base`, `debian:slim`, `ubi-minimal`, `rockylinux:minimal`, `amazonlinux`, `opensuse/leap`, `archlinux`, `busybox` and execute `install.sh` directly with env vars to mimic the wrapper (`VERSION=...`, `_REMOTE_USER=...`, `_REMOTE_USER_HOME=...`). Catches missing tar/curl/CA/bash assumptions, which the devcontainer CLI cannot do cheaply on bash-less images because its test lib is bash.
3. **End-to-end layer (devcontainer CLI)**: `scenarios.json` for the images users actually pull (mcr base ubuntu/debian/alpine, plus plain `alpine`, `debian`, `ubuntu`, `fedora`), with root and non-root `remoteUser`, pinned vs `latest`, and a duplicate-install scenario; run via the feature-starter three-job workflow. Use `#!/bin/sh` test scripts without the lib (or the `_ensure_bash.sh` bootstrap) on bash-less images.

## 5. Quality signals

Observed across the set; ordered roughly by how well they separate good from average:
- **Non-root correctness**: handles `_REMOTE_USER`/`automatic` and unknown users ([node #307](https://github.com/devcontainers/features/issues/307) was exactly this bug); tests with a non-root scenario (aqua `alpine-nonroot`, micromamba `*-non-root`, [micromamba tests](https://github.com/mamba-org/devcontainer-features/tree/main/test/micromamba)).
- **Integrity**: checksum/signature verification with escape hatch options (kubectl-helm-minikube, terraform, git-lfs, powershell); pinned upstream installer by commit (aqua). Most single-binary vendor features skip it (section 2).
- **Docs**: `NOTES.md` per feature including an "OS Support" section, rendered into README by `devcontainers/action` `generate-docs` ([common-utils NOTES](https://github.com/devcontainers/features/blob/main/src/common-utils/NOTES.md), [feature-starter release.yaml](https://github.com/devcontainers/feature-starter/blob/main/.github/workflows/release.yaml)). Spec requires `documentationURL`/`licenseURL` only optionally; vendors that omit them (Earthly, trunk) are less discoverable.
- **Layer size**: apt lists/apk cache cleanup, temporary downloader installs reverted (nanolayer `clean_download`), no leftover `/tmp` (trap on EXIT in Tailscale, Wolfi mise).
- **`installsAfter`** `ghcr.io/devcontainers/features/common-utils` (git, github-cli, node, dind, Doppler, feature-starter) so that bash/curl/user exist first; `ghcr.io/devcontainers/features/git`, `.../go`, `.../node` for ones that depend on them (github-cli, k6, claude-code). Soft only ([spec](https://github.com/devcontainers/spec/blob/main/docs/specs/devcontainer-features.md)); `dependsOn` is the hard form.
- **Lifecycle hooks / runtime wiring**: Tailscale uses `entrypoint`, `capAdd`, and a volume `mounts` entry ([json](https://github.com/tailscale/codespace/blob/main/src/tailscale/devcontainer-feature.json)); dind uses `privileged`, `entrypoint`. A plain CLI binary needs none.
- **Lint**: shellcheck only in devcontainers-extra CI (`shellcheck --severity=error -e SC2148 src/<f>/*.sh`, [test.yaml](https://github.com/devcontainers-extra/features/blob/main/.github/workflows/test.yaml)) and a `.shellcheckrc` in mamba-org; no shfmt found in any surveyed repo. devcontainers/features itself has no shellcheck job.
- **Automation**: Dependabot with `devcontainers` and `github-actions` ecosystems ([devcontainers/features](https://github.com/devcontainers/features/blob/main/.github/dependabot.yaml), rocker-org and eitsupi have `dependabot.yml`); Renovate in aqua ([renovate.json5](https://github.com/aquaproj/devcontainer-features/blob/main/renovate.json5)) and meaningful-ooo. Release by `devcontainers/action@v1` on `workflow_dispatch` (feature-starter) with the semantic version bumped manually in `devcontainer-feature.json`.
- **Multi-arch CI**: native `ubuntu-24.04-arm` matrix (eitsupi) is unusual and valuable for a binary installer.

## 6. Common mistakes / anti-patterns

Each with evidence:
- **Assuming apt/Debian.** trunk (`dpkg -s`, `apt-get` only), duckdb-cli (`dpkg --print-architecture`), github-cli, dind; Alpine regression in git ([#824](https://github.com/devcontainers/features/issues/824), distro check added in a later PR excluded Alpine; fixed later by [PR #1679](https://github.com/devcontainers/features/pull/1679)), python on Alpine with an unhelpful error ([#498](https://github.com/devcontainers/features/issues/498)). Fail early with a clear "unsupported distro" message instead.
- **Assuming bash / bash on bare Alpine.** `#!/usr/bin/env bash` -> exit 127 **[ran]**; devcontainers-extra's own comment notes Alpine lacks bash; Doppler and aqua must `apk add bash` for an upstream script; Doppler needed `_ensure_bash.sh` even for its test files.
- **Assuming curl/wget/CA certs/tar exist.** Earthly (wget only, no install); Debian/Ubuntu/Alpine images have no curl and no CA bundle, rpm-minimal images have no tar (inventory above). Probe, install the missing piece, remove it afterwards.
- **Unauthenticated GitHub rate limits and single points of failure.** [#1726](https://github.com/devcontainers/features/issues/1726), [#911](https://github.com/devcontainers/features/issues/911); error text ("could not read Username") hides the cause. Prefer redirect-following or direct `releases/latest/download` URLs over `git ls-remote`/REST; add retries and a clear message.
- **Writing to root's home or to the wrong user.** `_REMOTE_USER` may be `root` or a non-standard user; node hard-coded `vscode|node|codespace|uid 1000` ([#307](https://github.com/devcontainers/features/issues/307)); aqua's scenario sets `PATH=/root/.local/...` for root and `/home/vscode/...` for non-root by hand; `$_REMOTE_USER` used unguarded with `set -u`. Install system-wide to `/usr/local/bin` and avoid per-user state unless required; use `_REMOTE_USER_HOME` when needed.
- **No integrity check on downloaded binaries** and `curl | bash` of vendor scripts in the build (trunk, Doppler `latest`, claude-code yum path, bun alpine variant in cirolosapio).
- **Brittle version parsing**: `grep -oP` (GNU-only), `echo -e`/`echo -n` in `sh`, `${!var}`/`declare -g` bashisms copy-pasted across 11 scripts in 6 variants ([#1726](https://github.com/devcontainers/features/issues/1726) notes the duplication).
- **Hard-coded old base distro workarounds** (CentOS 7 vault sed in git/node) accumulate; avoid in a new feature.
- **No Alpine/other-distro test while claiming support.** The reference READMEs say "should work"; the explicit declaration mechanism ([spec #58](https://github.com/devcontainers/spec/issues/58)) never shipped, so only the scenario matrix tells users what is supported.
- **Silent scope drift**: devcontainers-extra now explicitly drops non-Debian ([#244](https://github.com/devcontainers-extra/features/issues/244)); a feature that promises broad coverage must own its test matrix.

## Recommendations for the ocx feature

**Verdict: `install.sh` must be POSIX `sh` (`#!/bin/sh`), not bash-required.**

Evidence for:
- Bash-required fails closed on bare `alpine`, Wolfi/Chainguard and busybox, with exit 127 before any logic runs (**[ran]**). Plain `alpine` is a first-class entry in the reference matrices; Wolfi has a community fork precisely because reference features break there.
- The CLI wrapper and the spec's own recommendation ("`sh` in Alpine"), the feature-starter, and 6 of the vendor single-binary features already use `/bin/sh`. Nothing in an ocx single-binary install needs arrays, `[[ ]]`, `declare -g` or `pipefail`.
- The bootstrap alternative (sh stub that installs bash then `exec`s, as in `common-utils` and aqua) buys bash for free only where a package manager works and the network is up; it adds a package install (layer size, failure point) just to run text munging. Use it only if a later requirement truly needs bash.

Coverage trade-off: POSIX sh costs a dialect discipline (no `[[`, no arrays, no `local`-free guarantee, no `echo -e/-n`, no `grep -P`, no `pipefail`, `printf` instead of `echo`) and a dash/busybox test leg; it gains Alpine, Wolfi/Chainguard, busybox-based and any image with `/bin/sh`. Bash-required would be fine for the Debian/Ubuntu/RHEL/Fedora/Arch/openSUSE/Amazon set (all ship bash, inventory above) and would give simpler code and the reference collection's helpers, but drops exactly the bash-less minimal/distroless-adjacent images the goal targets. `local` is accepted by dash, busybox ash and bash and is acceptable if tested on those; strict POSIX avoids it by using subshell functions or unique variable names.

Concrete design (all supported by evidence above):
1. `#!/bin/sh`, `set -eu`, no `pipefail`; run under `dash`, `busybox sh`, `bash --posix` in CI.
2. Classify the OS from `/etc/os-release` (`ID`, `ID_LIKE`) *and* package-manager probing (`apt-get`, `apk`, `dnf`, `microdnf`, `yum`, `zypper`, `pacman`, `tdnf`); tolerate a missing `/etc/os-release` (busybox) by falling back to probing; unknown distro: proceed if the prerequisites (downloader, CA certs, tar/gzip) are present, otherwise fail with an explicit message (do not hard-reject like `node`).
3. Prerequisite probe order: downloader `curl` then `wget`, then `tar`/`gzip`/`sha256sum`/CA bundle; install only the missing pieces with the matching package manager, mark them for removal, remove after (nanolayer `clean_download` pattern), clean apt lists/apk cache/dnf cache.
4. Arch: `uname -m` -> `x86_64|amd64`, `aarch64|arm64`, explicit error otherwise; libc detection (`/lib/ld-musl-*`, `ldd --version`) if ocx ships separate musl/glibc assets; prefer a static/musl build if available.
5. Version: `latest` resolved without `git ls-remote` or the REST API (release redirect, or a vendor-controlled `latest` URL); exact pins supported; `proposals` (not `enum`) for `version`.
6. Integrity: verify SHA-256 (or the vendor's signature) from a checksum file; the surveyed vendors mostly skip this, so doing it is a differentiator; allow an explicit opt-out for air-gapped cases only.
7. Install to `/usr/local/bin` as root; no per-user state, so `_REMOTE_USER` is only needed if ocx init/completions are written; if so use `_REMOTE_USER_HOME` and handle root/unset/unknown users. No PATH wiring is needed for `/usr/local/bin`; if ocx also needs a data/shim directory, use `containerEnv`, not rc edits.
8. Idempotence: overwrite-by-rename (`install -m 0755` to a temp name then `mv`), skip when the requested version is already installed.
9. `installsAfter: ["ghcr.io/devcontainers/features/common-utils"]` (soft ordering, matches Doppler/git/github-cli); do not `dependsOn` it.
10. Options: `version` (default `latest`, `proposals`) and at most one or two advanced knobs (install dir only if a user need appears; avoid `*_SHA256` sprawl).
11. Testing: the three-layer split in section 4 (stub/dialect unit layer, per-image direct runs, devcontainer CLI scenarios), CI from the feature-starter three-job template extended with an arm64 runner and a plain-`alpine`, `wolfi-base`, `debian:slim`, `ubi-minimal`/`rockylinux:minimal` leg. Because `dev-container-features-test-lib` is bash, write `test.sh` for bash-less images as POSIX without the lib (or bootstrap bash like Doppler's `_ensure_bash.sh`). Add shellcheck (`--shell=sh`) and shfmt; the surveyed ecosystem mostly lacks both.
12. Declared support matrix in `NOTES.md` ("OS Support") must equal the scenario matrix; spec issue [#58](https://github.com/devcontainers/spec/issues/58) means nothing else declares it.

## Not verified / open

- **ocx's own constraints are not applied here**: archive format (tar.gz vs zip vs raw), published checksums/signatures, musl vs glibc assets, whether ocx must run any post-install step needing bash or a user home. Recommendations 3-6 depend on this.
- No script was executed end to end on any distro other than the quick shebang/`echo -e` probes; the inventory table and the `bash` exit-127 result are the only **[ran]** facts. Claims about dash/busybox behaviour of `local`, `echo -n`, `grep -P` are from standard behaviour and source reading, not run against each script.
- Wolfi `mise` test matrix, cirolosapio and bartventer test workflows, coder `code-server`, Dapr, aqua's `renovate.json5` contents, devcontainers-extra scenarios for individual features and the `gh-release` feature were not read in detail. The nanolayer repository itself was not read (only its consumers).
- bats: absence is based on filename/tree scans of 15 repos plus GitHub search (which can miss content); other repos may use it. brokenpip3/devcontainers-bats internals not read.
- Index search for 1Password, Pulumi, HashiCorp, astral/uv, deno, bun, pixi, nix, just vendor-owned features found no owner repos under the guessed paths; absence under those exact names is not proof they do not exist elsewhere (e.g. in `devcontainers-community` or a differently named org).
- openSUSE, Arch, Amazon Linux 2023, Wolfi are covered only by forks/our own image inventory; whether the reference `common-utils` supports them in practice was not tested (`common-utils/main.sh` recognises debian/rhel/alpine only in the lines read).
- Exact date/behaviour of the `/etc/os-release` absence on `busybox:1.36` and of `ca-certificates` paths on openSUSE Leap (bundle path differs from the two probed) are as observed on 2026-11-16 and may change with image updates.
- Whether Dependabot's `devcontainers` ecosystem bumps feature *versions* or only referenced features/images was not checked.
